# PhysioCare — วิเคราะห์คู่แข่งและแผนปรับปรุง

*สำรวจ ณ ตุลาคม 2026 จากเว็บไซต์ผู้ผลิต, หน้าราคา, เอกสารช่วยเหลือ, รีวิว (Capterra, G2, GetApp, Software Advice), รายงานอิสระ (PHTI 2024) และงานวิจัย ข้อมูลที่ตรวจสอบไม่ได้มีหมายเหตุ "ยังไม่ยืนยัน" กำกับ ตัวเลขผลลัพธ์ของผลิตภัณฑ์ส่วนใหญ่มาจากผู้ผลิตเอง*

## 1. สรุปสำหรับผู้บริหาร

**สิ่งที่เรามีแต่ตลาดยังไม่มี** — จากการสำรวจ 11 โปรแกรมสากลและ 7 โปรแกรมไทย ไม่พบโปรแกรมใดที่ทำได้ครบ:
1. จองนัดโดยตรวจความขัดแย้งของ **นักกายภาพ + อุปกรณ์ + ผู้ป่วย พร้อมกัน** (Jane มีเฉพาะแพ็กเกจแพงสุดและเอกสารเองบอกว่าตั้งค่า "ยาก", Nookal ยัง "coming soon")
2. **สถานะอุปกรณ์แบบ real-time** (พร้อมใช้ / กำลังใช้ / ซ่อม) — ไม่พบในผลิตภัณฑ์ใดเลย
3. **แนะนำนักกายภาพและอุปกรณ์จากการวินิจฉัย** + **คลังแนวทางเวชปฏิบัติพร้อมระดับหลักฐาน** — คู่แข่งใช้ AI แค่ช่วยเขียนบันทึก ไม่มี clinical decision support
4. **ROM/Pain เป็นข้อมูลโครงสร้างพร้อมกราฟความก้าวหน้า** — คู่แข่งส่วนใหญ่เก็บเป็นข้อความหรือพึ่งโปรแกรมภายนอก (Physitrack)

**สิ่งที่ตลาดมีเป็นมาตรฐานแต่เรายังขาด** — ถ้าไม่มี คลินิกจะไม่เปลี่ยนมาใช้:
1. ผู้ป่วยจองเอง / แบบฟอร์มคัดกรองก่อนมา (intake)
2. แจ้งเตือนนัด (SMS / **LINE** ในไทย) และ waitlist เติมช่องว่างที่ยกเลิก
3. คอร์ส/แพ็กเกจหลายครั้ง ตัดรอบอัตโนมัติ, การเงิน ใบเสร็จ, ค่ามือนักกายภาพ
4. นัดต่อเนื่องตามแผนการรักษา (recurring), Home exercise program

**โอกาสที่ชัดที่สุด:** ผสาน "ประเมินเบื้องต้น → จัดสรรคน+อุปกรณ์ → หาวันเวลา" เข้ากับช่องทาง **LINE** — ระบบคัดกรองอัตโนมัติในต่างประเทศ (Phio, Flok) หยุดที่ "ส่งต่อเส้นทางการรักษา" ไม่มีระบบใดจองเข้าตารางของนักกายภาพที่เหมาะสมพร้อมอุปกรณ์ได้ ส่วนโปรแกรมไทยมี LINE แต่ไม่มีตรรกะทางคลินิกเลย

## 3. ระบบคัดกรองอัตโนมัติและการจัดสรรอัจฉริยะ

| ผลิตภัณฑ์ | วิธีคัดกรอง | จัดสรรนักกายภาพ | จองช่องเวลา | หลักฐาน / กำกับดูแล | จุดอ่อน |
|---|---|---|---|---|---|
| Phio Access (UK, 11 NHS sites) | แบบถามตอบปรับตามคำตอบ >3,000 scenario | ระดับเส้นทางการรักษา | ผ่านหน่วยบริการ (ยังไม่ยืนยัน) | ผลรายงานโดย NHS trust | คัดกรองเกินเป็น "เร่งด่วน" (~14% ไม่ตรงกับนักกายภาพ ทุกรายเป็นการ over-triage) |
| Flok Health (UK) | AI อัตโนมัติทั้งหมด | ไม่ (AI รักษาเอง) | ไม่ | ข้อมูล pilot ของบริษัท | อ้างความปลอดภัยเอง |
| Sword / Hinge Health (US) | แบบสอบถาม + AI + นักกายภาพ | กำหนดนักกายภาพออนไลน์ | ออนไลน์เป็นหลัก | PHTI 2024: แบบมีนักกายภาพนำได้ผล | หลักฐานส่วนใหญ่มาจากบริษัท |
| Jane / Cliniko | ไม่มี | คนเลือกเอง | waitlist | – | ไม่มีตรรกะความเชี่ยวชาญ/อุปกรณ์ |
| LeanTaaS / Qventus | – | – | ทำนายความต้องการ, ปล่อยช่องว่าง | case study ผู้ผลิต | ระดับโรงพยาบาล ราคาสูง |
| **PhysioCare** | ✗ (ยังไม่มีแบบประเมินก่อนจอง) | **✓ คะแนนความเชี่ยวชาญ/ต่อเนื่อง/ภาระงาน** | **✓ slot finder + กันชน** | กฎอธิบายได้ | ยังต้องให้เจ้าหน้าที่กรอกเริ่มต้น |

**บทเรียนจากงานวิจัย**
- ระบบตรวจอาการอัตโนมัติส่วนใหญ่แม่นยำไม่พอ (9 ใน 13 การศึกษา) และ red flags แต่ละข้อมีหลักฐานความแม่นยำจำกัด → IFOMPT แนะนำใช้เป็นกระบวนการคิดทางคลินิก **ต้องมีนักกายภาพยืนยันเสมอ**
- STarT Back แบ่งกลุ่มความเสี่ยงแล้วรักษาตามกลุ่ม ได้ผลดีกว่าการรักษาปกติ (Lancet 2011, อยู่ใน NICE) แต่ STarT MSK ไม่ดีกว่า → คะแนนอย่างเดียวไม่พอ ต้องผูกกับแผนการรักษา
- SMS เตือนนัดดีกว่าไม่เตือน (Cochrane) และถูกกว่าการโทร; การทำนาย no-show ในกายภาพทำได้ระดับ c-statistic ~0.72 แต่ positive predictive value ต่ำ → overbook อย่างระมัดระวังเท่านั้น
- ผู้ป่วยกายภาพ ~10% ไม่มานัดประเมินครั้งแรก และเสี่ยงมากขึ้นเมื่อรอนาน
- การจัดตารางฟื้นฟูในงานวิจัยใช้ constraint solving 2 ขั้น (เลือกนักกายภาพ → เลือกเวลา) เพราะ integer programming แก้ปัญหาขนาดจริงไม่ทัน
- **อย.ไทย** มีแนวทางซอฟต์แวร์ที่เป็นเครื่องมือแพทย์ (2024) ครอบคลุม AI คัดกรอง/ให้คะแนนความเสี่ยง และบังคับ UDI สำหรับ class 2–4 ตั้งแต่ 20 มิ.ย. 2026 → วางตำแหน่งเวอร์ชันแรกเป็น "เครื่องมือช่วยตัดสินใจ" ที่บุคลากรยืนยัน

**ทุกโปรแกรมไทยที่พบ:** ไม่มีตรรกะทางคลินิก, ไม่จัดสรรอุปกรณ์, ไม่มีระบบเบิก สปสช. และไม่ระบุ PromptPay ชัดเจน

**ข้อกำหนดเฉพาะไทยที่ต้องรองรับ**
- **สปสช.:** คลินิกกายภาพร่วมบริการได้ 2 ทาง
  - ฟื้นฟูระยะกลาง (IMC) 4 กลุ่มโรค ได้แก่ หลอดเลือดสมอง, บาดเจ็บสมอง, ไขสันหลัง และสะโพกหักในผู้อายุ 50+ อัตรา 450 บาท/ครั้ง สูงสุด 20 ครั้งใน 6 เดือน (ยังไม่ยืนยันว่าเป็นอัตราปัจจุบัน) ต้องมีใบส่งตัว
  - "30 บาทรักษาทุกที่" ผู้ป่วย walk-in ด้วยบัตรประชาชน
  - ทั้งสองทางต้องยืนยันตัวตนให้ได้ Authen Code และส่งเบิกผ่าน e-Claim (ต้องใช้ 2FA ตั้งแต่ มิ.ย. 2026)
  - ปัจจุบันมีคลินิกร่วมบริการเพียง ~68 แห่ง จาก >800 แห่ง → ระบบที่ช่วยเรื่องการเบิกเป็นตัวช่วยตัดสินใจเข้าร่วม
- **PDPA:** ข้อมูลสุขภาพเป็นข้อมูลอ่อนไหว (มาตรา 26) ต้องได้ความยินยอมชัดแจ้ง แจ้งเหตุรั่วไหลภายใน 72 ชม. และทำสัญญาประมวลผลข้อมูลกับผู้ให้บริการซอฟต์แวร์
- **พ.ร.บ.สถานพยาบาล 2541:** เก็บเวชระเบียนให้ตรวจสอบได้ (ข่าวระบุอย่างน้อย 5 ปี — ควรตรวจกับกฎกระทรวง) และใส่เลขใบอนุญาต ก.ภ. ในบันทึก
- **ช่องทางที่ผู้ป่วยคาดหวัง:** LINE OA/LIFF, PromptPay QR, คอร์สแพ็กเกจพร้อมวันหมดอายุ, อ่านบัตรประชาชน, วันที่แบบ พ.ศ.
- **อนาคต:** ส่งออก FHIR (MoPH Primary Care 1) เชื่อม MOPH Health Link

## 5. จุดแข็ง–จุดอ่อนของ PhysioCare (ประเมินตามจริง)

**จุดแข็ง**
- ตรรกะจัดสรรคน+อุปกรณ์+เวลา ที่อธิบายเหตุผลได้และกันชนระดับฐานข้อมูล
- ความปลอดภัยทางคลินิก: ข้อห้ามใช้อุปกรณ์ตาม precaution, บังคับ pre-assessment ก่อนเริ่มรักษา, ลงนามแล้วแก้ไม่ได้
- ฐานความรู้ตามหลักฐานพร้อมแหล่งอ้างอิง
- ข้อมูล ROM/Pain เป็นโครงสร้าง ใช้ทำรายงานผลลัพธ์ทางคลินิกได้
- ภาษาไทย, RBAC ตามหลัก least privilege, audit log, รันบนเซิร์ฟเวอร์ในไทยได้

**จุดอ่อน / ความเสี่ยง**
- ยังไม่มีงานหน้าร้าน: การเงิน คอร์ส ใบเสร็จ ค่ามือ, แจ้งเตือน, LINE, ผู้ป่วยจองเอง
- ยังไม่มีแบบประเมินเบื้องต้นก่อนจอง (ตรงกับเป้าหมาย "ประเมิน → จัดสรร → หาวันเวลา" ที่ต้องการ)
- ยังไม่มีนัดต่อเนื่องตามแผนการรักษาและ waitlist
- ยังไม่มี body chart, HEP, PROMs มาตรฐาน (ODI, NDI, KOOS ฯลฯ), AI ช่วยเขียนบันทึก
- ยังไม่รองรับหลายสาขา, ยังไม่เคยใช้งานจริง (ยังไม่ผ่านการทดสอบโหลด/ความปลอดภัย)
- ค่าน้ำหนักจับคู่ความเชี่ยวชาญยังเป็นค่าตัวอย่าง

## 6. แผนปรับปรุง (เรียงตามลำดับความสำคัญ)

### P0 — ทำให้ "ประเมิน → จัดสรร → หาวันเวลา" ครบวงจร (จุดขายหลัก)
1. **แบบประเมินเบื้องต้น (Intake & Triage)**
   - คัดกรอง red flags ตามบริเวณร่างกาย (อิง IFOMPT) เป็นขั้นแรก: ถ้าพบ → แจ้งให้ไปพบแพทย์/ฉุกเฉิน + แจ้งเตือนนักกายภาพ **ไม่จองนัด**
   - แบบประเมินมาตรฐาน: NPRS (pain), PSFS, STarT Back (หลัง), Keele STarT MSK (บริเวณอื่น), แบบเฉพาะบริเวณ (ODI, NDI, QuickDASH, KOOS-JR, SPADI) — ใช้ฉบับภาษาไทยที่ผ่านการแปลและทดสอบแล้ว และตรวจเรื่องสิทธิ์การใช้งาน
   - ผลลัพธ์ = ความเร่งด่วน + บริเวณ + กลุ่มความเสี่ยง + ความต้องการ (ความเชี่ยวชาญ, อุปกรณ์, ระยะเวลา) ส่งต่อให้ระบบจัดสรร
   - คะแนนชุดแรกใช้เป็น baseline ของ outcome tracking
2. **จัดสรรอัตโนมัติพร้อมตัวเลือก 2–3 ช่อง** พร้อมเหตุผล (เช่น "ผู้เชี่ยวชาญเข่า + เครื่อง X ว่าง อังคาร 10:00") กำหนดเพดานเวลารอตามความเร่งด่วน, เจ้าหน้าที่/นักกายภาพยืนยันหรือเปลี่ยน และบันทึกการเปลี่ยนไว้ปรับกฎ
3. **นัดต่อเนื่องตามแผนการรักษา** (เช่น 2 ครั้ง/สัปดาห์ × 6 สัปดาห์) จองทั้งชุดพร้อมกันโดยใช้ engine กันชนเดิม

### P1 — สิ่งที่ตลาดไทยต้องมี
4. **LINE OA + LIFF:** แบบประเมินผ่าน LINE, เลือกช่องเวลา, เตือนนัด, ยืนยัน/เลื่อนเอง, ดูคอร์สคงเหลือ
5. **คอร์ส/แพ็กเกจ + การเงิน:** ตัดรอบอัตโนมัติ, วันหมดอายุ, มัดจำ, PromptPay QR, ใบเสร็จ/ใบกำกับภาษี, ใบรับรองแพทย์สำหรับเบิกประกัน, ค่ามือนักกายภาพ
6. **Waitlist + no-show:** เติมช่องที่ยกเลิกอัตโนมัติผ่าน LINE, ให้คะแนนความเสี่ยง no-show แบบง่าย (ประวัติยกเลิก, ระยะเวลารอ) เพื่อเตือนถี่ขึ้น
7. **ชุด PDPA:** บันทึกความยินยอม, privacy notice, กำหนดระยะเก็บข้อมูล, ขั้นตอนแจ้งเหตุรั่วไหล

### P2 — ขยายความสามารถทางคลินิกและการเชื่อมต่อ
8. Outcome measures มาตรฐานพร้อมกราฟ + body chart + เลขใบอนุญาต ก.ภ. ในทุกบันทึก
9. Home exercise program (คลิปภาษาไทย) ส่งผ่าน LINE + ติดตามการทำ
10. **ระบบเบิก สปสช.:** IMC 4 กลุ่มโรคและ "30 บาทรักษาทุกที่" — รับใบส่งตัว, Authen Code, นับครั้ง 20 ครั้ง, ส่งออกข้อมูลเบิก
11. AI ช่วยร่าง progress note จาก Pain/ROM (ให้นักกายภาพแก้และลงนาม) — ข้อมูลไม่ออกนอกระบบหรือมีสัญญาประมวลผลข้อมูล
12. หลายสาขา, อ่านบัตรประชาชน, ส่งออก FHIR MoPH PC1, จัดตารางทั้งสัปดาห์ด้วย constraint solver (OR-Tools CP-SAT)

### หลักการที่ควรคงไว้
- กฎอธิบายได้ (ไม่ใช่ black-box), มีกฎหลายเวอร์ชันและ audit log
- บุคลากรยืนยันทุกการตัดสินใจอัตโนมัติ, red flags ต้องเอนเอียงไปทางระวังไว้ก่อน (sensitivity สูง)
- ราคาแบบรวมทุกอย่าง ไม่แยก add-on (ลูกค้าในตลาดบ่นเรื่องนี้มาก)
- เก็บข้อมูลในประเทศไทย
