# PhysioCare Management System

ระบบบริหารจัดการห้องกายภาพบำบัด ประกอบด้วยทะเบียนอุปกรณ์และบุคลากร ระบบนัดหมายที่กันการจองซ้อนพร้อมแนะนำนักกายภาพและอุปกรณ์ตามการวินิจฉัย เวชระเบียนก่อน/หลังการรักษา และสิทธิ์การใช้งานตามบทบาท

- **Backend:** Node.js 20+ / Express 5 / PostgreSQL 14+
- **Frontend:** Tailwind CSS + Vanilla JS (ES Modules) ไม่ต้อง build

รายละเอียดสถาปัตยกรรม, ER diagram, อัลกอริทึม และ API ทั้งหมดอยู่ที่ [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) · วิเคราะห์คู่แข่งและแผนปรับปรุงอยู่ที่ [docs/COMPETITIVE_ANALYSIS.md](docs/COMPETITIVE_ANALYSIS.md)

## ฟีเจอร์

| โมดูล | ความสามารถ |
|---|---|
| Equipment Master | สถานะ real-time (พร้อมใช้ / กำลังใช้ / ส่งซ่อม / ชำรุด / จำหน่าย), หมวดหมู่, วันที่ซื้อ/ราคา/ประกัน, ประวัติบำรุงรักษาและค่าใช้จ่าย, รอบ PM อัตโนมัติ, timeline สถานะ, แจ้งชำรุดแล้วแสดงนัดที่กระทบและเครื่องทดแทน |
| Staff Master | ความเชี่ยวชาญ (Orthopedic, Neurological, Pediatric, Sports, Cardio, Geriatric) ระดับ 1–5, ใบอนุญาต, ตารางกะรายสัปดาห์, สร้างกะแบบ bulk, วันลา |
| รูปภาพ | อัปโหลดรูปของอุปกรณ์ บุคลากร ผู้ป่วย เวชระเบียน และงานซ่อม ตรวจชนิดไฟล์จาก magic bytes และตรวจสิทธิ์ก่อนเสิร์ฟ |
| ห้อง & เตียง | ทะเบียนห้อง (ห้องรักษา, ห้องส่วนตัว, gym, ห้องเด็ก) พร้อมความจุ และเตียงพร้อมสถานะ, อุปกรณ์ติดตั้งประจำห้อง, จัดห้อง/เตียงให้อัตโนมัติตอนหาเวลาและจอง, เผื่อเวลาเปลี่ยนผ้าปู, ผังเตียงแบบ real-time (ว่าง/มีผู้ป่วย/ปิดซ่อม), ปิดเตียงแล้วแสดงนัดที่ต้องย้ายพร้อมเตียงทดแทน |
| ปฏิทินนัดหมาย | มุมมองวัน (แยกคอลัมน์ต่อนักกายภาพ แรเงาช่วงนอกกะ/วันลา), ตามเตียง (คอลัมน์ต่อเตียง/ห้อง gym), สัปดาห์ (นัดที่เวลาซ้อนกันวางเคียงกัน) และเดือน, กรองตามนักกายภาพ, อัปเดตอัตโนมัติเมื่อมีการจอง/เปลี่ยนสถานะ |
| Smart Scheduling | กันจองซ้อนทั้งบุคลากร ผู้ป่วย อุปกรณ์ และเตียง/ห้อง 3 ชั้น (ตรวจในแอป → row lock → EXCLUDE constraint), เผื่อเวลาทำความสะอาดเครื่อง, ตรวจกะ/วันลา/ช่วงปิดซ่อม, เสนอช่วงเวลา/คน/เครื่องทดแทนเมื่อชน, optimistic locking ตอนเลื่อนนัด |
| แนวทางการรักษา (CPG) | 13 โรค อ้างอิง 21 แนวทางเวชปฏิบัติ (JOSPT/APTA, NICE, ACP, OARSI, ACR, AHA/ASA, ANPT, Novak/Jackman CP): วิธีรักษาที่ไม่ใช้อุปกรณ์พร้อมขนาด/ความถี่, ระดับคำแนะนำ + เกรดหลักฐานของแต่ละอุปกรณ์, red flags และลิงก์แหล่งอ้างอิง แสดงในหน้า "แนวทางการรักษา", หน้าจองนัด และหน้าเวชระเบียน |
| Recommendation | จับคู่การวินิจฉัย (ICD-10) กับความเชี่ยวชาญและหมวดอุปกรณ์, คิดคะแนนจากความเชี่ยวชาญ ความต่อเนื่อง ภาระงาน และความว่าง, ตัดอุปกรณ์ที่ห้ามใช้ตามข้อควรระวังของผู้ป่วย (pacemaker, ตั้งครรภ์, โลหะในร่างกาย ฯลฯ) และไม่แนะนำอุปกรณ์ที่แนวทางเวชปฏิบัติระบุว่าไม่ควรใช้ |
| EMR | Pre-assessment (Pain NRS, ROM, vital signs, ข้อควรระวัง), Post progress note (ผลตอบสนอง, การรักษาที่ใช้อุปกรณ์, home program), ลงนามแล้วแก้ไม่ได้ (เพิ่มเติมได้ทาง addendum), กราฟความก้าวหน้าเทียบกับครั้งแรกและครั้งก่อน |
| RBAC | Admin / Therapist / Staff / Patient ตรวจสิทธิ์ระดับ permission, ผู้ป่วยเห็นเฉพาะนัดของตนเอง, audit log |

## เริ่มใช้งาน

ต้องมี Node.js 20 ขึ้นไป และ PostgreSQL 14 ขึ้นไป

### ทดลองบนเครื่องตัวเอง (มีข้อมูลตัวอย่าง)

```bash
createdb physiocare
cd backend
cp .env.example .env        # แก้ DATABASE_URL และ JWT_SECRET
npm install
node --env-file=.env scripts/migrate.js --demo   # schema + ข้อมูลอ้างอิง + แนวทางการรักษา + ข้อมูลทดลอง
node --env-file=.env src/server.js
# เปิด http://localhost:3000
```

### ใช้งานจริง (production)

ใช้ Docker Compose (แอป + PostgreSQL + HTTPS อัตโนมัติ + สำรองข้อมูลรายวัน) ตามคู่มือ [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md) — production จะ **ไม่มี** ข้อมูลทดลองและบัญชี `Passw0rd!` ให้สร้างผู้ดูแลระบบคนแรกด้วย `npm run create-admin`

### โครงสร้างไฟล์ฐานข้อมูล

| ไฟล์ | เนื้อหา | Production |
|---|---|:-:|
| `db/001_schema.sql` | ตาราง, constraint, trigger, view | ✓ |
| `db/002_reference_data.sql` | บทบาท/สิทธิ์, ตั้งค่า, ความเชี่ยวชาญ, หมวดอุปกรณ์, ICD-10, ข้อห้ามใช้ | ✓ |
| `db/003_clinical_guidelines.sql` | ฐานความรู้แนวทางการรักษา (รันซ้ำอัตโนมัติเมื่อแก้ไข) | ✓ |
| `db/004_rooms_beds.sql` | ห้อง/เตียง และการจองเตียง | ✓ |
| `db/demo/101_demo_data.sql` | บุคลากร ผู้ป่วย อุปกรณ์ บัญชีทดลอง | ✗ |
| `db/demo/102_demo_appointments.sql` | นัดตัวอย่าง ~260 รายการ | ✗ |
| `db/demo/103_demo_rooms_beds.sql` | ห้อง 7 ห้อง เตียง 13 เตียง และจัดเตียงให้นัดตัวอย่าง | ✗ |

`scripts/migrate.js` บันทึกไฟล์ที่รันแล้วในตาราง `schema_migrations` — การแก้ schema ครั้งต่อไปให้เพิ่มไฟล์ใหม่ เช่น `db/004_xxx.sql` (ฐานข้อมูลที่เคยสร้างด้วย `psql` ก่อนหน้านี้ ให้รัน `scripts/migrate.js --baseline` หนึ่งครั้ง)

## การทดสอบ

Integration test 29 กรณี รันกับ PostgreSQL จริง ครอบคลุมการจองซ้อน, คำขอจองพร้อมกัน, ข้อห้ามใช้อุปกรณ์, RBAC, การล็อกเวชระเบียน, การ push ผ่าน SSE และการอัปโหลดรูป

```bash
createdb physiocare_test
cd backend
DATABASE_URL=postgres://localhost/physiocare_test npm test   # ⚠ จะล้าง schema ของฐานข้อมูลนี้
```

> ⚠ ความเชื่อมโยงระหว่างโรค ความเชี่ยวชาญ และอุปกรณ์ รวมถึงกฎข้อห้ามใช้ใน `db/002_reference_data.sql` เป็นข้อมูลตัวอย่าง ต้องให้นักกายภาพบำบัดตรวจรับรองก่อนใช้งานจริง
